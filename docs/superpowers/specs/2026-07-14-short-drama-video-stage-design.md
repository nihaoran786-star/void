# AI 短剧视频舞台优化设计

## 目标

修复首个视频点击后无法稳定播放的问题，并将视频页改为简洁、高效、随面板宽度自适应的单播放器审片界面。分页、短剧项目状态、生成流程、媒体恢复和后端接口保持不变。

## 根因

首个静态视频文件和 HTTP 服务正常：文件为 H.264 Baseline + AAC，服务支持字节范围请求。故障位于 React 播放器生命周期：主视频节点的 `key` 同时包含媒体 URL 和异步生成的海报 URL。首帧提取完成后海报 URL 改变，React 销毁并重建正在播放的 `<video>`，导致播放被中断。

视频页还为主播放器和每个场景条目分别创建首帧解码任务；没有缩略图时，场景条目甚至直接创建额外 `<video>`。这增加了启动延迟、内存占用和播放竞争。

## 交互设计

采用“单主播放器 + 底部胶片条”：

- 页面只渲染当前选中场景的一个可播放 `<video>`。
- 主播放器上方显示当前场景序号、总数和标题。
- 提示词/摘要位于播放器下方，避免覆盖画面。
- 场景胶片条位于内容底部，横向滚动；每项只显示静态缩略图或轻量占位。
- 选择场景只切换当前主播放器，不自动播放，也不修改分页状态。
- 当前场景使用明确的选中状态、`aria-selected` 和可见序号。
- 打开全局预览继续使用媒体预览组件已有的独立操作按钮。

## 响应式

- 胶片条在所有宽度保持横向排列，避免左右栏在拖窄时跳变。
- 宽面板显示较大的胶片项和完整标题。
- 620px 以下缩小胶片项；420px 以下隐藏次要摘要，但保留播放器、选择、播放和分页。
- 响应式继续由 `short-drama-panel` Container Query 驱动，不依赖整个窗口宽度。

## 播放器生命周期

- `<video key>` 只使用稳定的媒体 URL。
- 删除主播放器的异步首帧提取；优先使用已有 thumbnail/poster。
- 场景胶片条不创建 `<video>`，没有缩略图时展示占位状态。
- 切换场景时 React 仅因媒体 URL 改变而重建播放器，确保播放状态与媒体一一对应。

## 边界

允许修改：

- `ShortDramaCenterPanel.tsx` 中 `VideoStage`、`MediaPreview` 和场景缩略图展示。
- `ShortDramaCenterPanel.scss` 中视频舞台、胶片条和容器响应式样式。
- 视频舞台布局/生命周期契约测试。

禁止修改：

- `ShortDramaEpisodeNavigationState` 及其测试。
- 项目 ViewModel、store、生成和媒体恢复接口。
- Tauri、文件系统和后端适配器。

## 验证标准

- 首个视频开始播放后，异步缩略图变化不会重建播放器。
- 视频页同时最多存在一个真实播放器节点。
- 场景胶片条只包含图片或占位，不包含视频节点。
- 选择任意场景后，标题、序号和主播放器同步更新。
- 620px 与 420px 容器宽度下不横向撑破面板。
- 分页文件零 diff；相关测试、类型检查和 Web 构建通过。
