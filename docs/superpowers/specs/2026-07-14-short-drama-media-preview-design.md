# AI 短剧媒体预览与布局优化设计

## 目标

在不改变分页、生成流程、项目状态和后端接口的前提下，重做 AI 短剧面板的图片与视频预览布局，使主媒体始终完整可见，并让布局随用户拖拽后的面板实际宽度变化。

## 设计方向

采用“媒体优先的紧凑编辑台”：主预览占据视觉中心，导航和元数据退居次要层级。沿用现有深色主题和语义化颜色，不引入新的主题体系、装饰性渐变或复杂动画。

## 范围

允许修改：

- 短剧面板内的媒体预览组件和相关样式。
- 短剧媒体预览 ViewModel 中用于展示的宽、高和宽高比字段。
- 覆盖媒体 ViewModel、布局契约和分页不变性的测试。

明确不修改：

- 分页组件、分页状态、页码计算和翻页事件。
- 短剧生成、编排、持久化和媒体恢复流程。
- 工作区媒体扫描接口和后端接口。
- 全局媒体预览浮层的行为。

## 布局

### 主预览

- 图片和视频使用 `object-fit: contain`，任何比例都完整显示。
- 媒体舞台使用中性背景，并依据可用宽度与高度约束，不再强制所有媒体裁切成 16:9。
- 已知媒体比例时使用 ViewModel 提供的比例；未知时图片使用 1:1、视频使用 16:9 作为稳定占位，媒体加载后仍以完整显示为最高优先级。
- 标题、时长和状态位于媒体舞台外，不覆盖画面。

### 缩略导航

- 缩略图允许使用 `cover`，因为其职责是快速识别与切换，而不是精确审图。
- 宽面板保留垂直缩略轨道；面板变窄时转为主预览上方的水平缩略轨道。
- 当前项继续复用既有选中状态和点击事件，不改变分页或业务逻辑。

### 容器响应式

- 在短剧中心面板根节点启用 `container-type: inline-size`。
- 使用内容驱动的 Container Query，而不是窗口级 Media Query：
  - 宽：垂直轨道与主预览并排。
  - 中：轨道变为水平滚动，主预览占满宽度。
  - 窄：压缩非关键间距和元数据，但保留预览、切换和分页能力。
- 不隐藏分页、播放或选择等核心功能。

## 视频交互和性能

- 原生视频控件不再通过事件冒泡触发“打开大预览”。
- “打开大预览”使用独立、明确的操作区域。
- 视频首帧海报只覆盖媒体内容区，不假设原生控件固定为 48px 高。
- 本轮只优化当前布局所需行为；更大范围的缩略图缓存与媒体解码调度不纳入本次改动。

## 数据流

```text
WorkspaceMediaItem
  -> ShortDramaMediaPreviewViewModel（补充 width / height / aspectRatio）
  -> ShortDramaCenterPanel（只渲染状态）
  -> CSS Container Query（只决定排列，不推断媒体来源）
```

ViewModel 从工作区媒体读取宽高或占位比例并输出规范化的 CSS 宽高比。UI 不访问文件系统、不判断媒体来源、不调用 Tauri。

## 验证标准

- 9:16、1:1、4:3、16:9 和 21:9 图片在主预览中不裁切。
- 面板在宽、中、窄三种拖拽宽度下不发生横向溢出，主预览与分页均可操作。
- 缩略图选择、原生视频播放、打开全局预览各自独立。
- 既有分页文件和分页状态逻辑无 diff。
- 相关单元测试、Web UI 类型检查通过。

## 风险控制

- 不重构短剧业务状态，不拆改分页链路。
- 样式选择器限定在短剧中心面板命名空间内。
- ViewModel 只增加可选展示字段，避免破坏既有调用方和旧项目数据。
