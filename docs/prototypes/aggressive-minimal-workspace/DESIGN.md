# AI 短剧工作区：激进极简设计提案

> 状态：视觉原型，尚未接入产品运行时。  
> 核心约束：不删除功能、不绕过现有事件和服务、不改变生成、预览、引用、团队切换与短剧五阶段调用链。

## 1. 结论

不建议把 A / B / C 做成三个需要用户选择的永久模式。推荐组合为：

- **A — Codex Core 是默认骨架**：保留左导航和完整对话，AI 短剧改为按需右侧面板。
- **B — Media Focus 是临时状态**：用户打开某张分镜、视频或成片时，只放大当前媒体，其余内容收为底部胶片条。
- **C — Command Stream 是内容模式**：媒体生成、资产、分镜、代理和工具结果默认显示为紧凑结果行，选中后展开现有完整组件。

用户感受到的是一个界面，而不是三个模式：

```text
默认对话
  ├─ 打开 AI 短剧 → 右侧按需面板
  ├─ 打开媒体 → 临时媒体聚焦
  └─ 展开结果行 → 原完整详情和现有操作
```

## 2. 当前基线暴露的问题

当前 Void 全窗口同时存在四个横向区域：左导航、聊天、短剧面板、团队 rail。聊天头部在条件齐全时最多出现约 11 个动作面，媒体库工具栏最多约 13 个控件；分镜卡还会同时显示 1 张主图和最多 6 张参考图。

最需要治理的不是颜色，而是**永久可见的信息过多**：

1. 很多低频动作与主任务同等突出。
2. 图片在聊天、分镜、资产和媒体工具结果中重复占据大面积。
3. 团队代理逐个常驻为图标，状态有价值，但空间利用率低。
4. 无数据阶段显示大面积空白，缺少紧凑状态和下一步入口。
5. 左导航同时承担模式入口、工作区、会话和工具入口，层级过多。

## 3. 推荐布局

### 默认：Codex Core

| 区域 | 目标尺寸 | 默认显示 |
|---|---:|---|
| 应用顶栏 | 44px | 当前任务、必要状态、一个 overflow |
| 左导航 | 220px | 新建、搜索、当前工作区、最近会话 |
| 对话正文 | min 680px / max 760px 文本行宽 | 消息、紧凑结果行、输入框 |
| AI 短剧 | 360–400px 按需面板 | 五阶段文本 tab、当前阶段内容 |
| 团队 | 不再永久占独立 rail | 顶部“团队 5”聚合入口，打开后显示完整代理列表 |

左导航收窄不等于删除入口。助理、自动化、定制、终端、浏览器等低频入口进入“更多”；三个新建会话入口合并为一个 split menu，原命令和快捷键继续存在。

### 媒体聚焦

用户点击资产、分镜、视频或成片后：

- 中央只显示当前选中媒体；
- 对话收为窄列但不卸载；
- 同组媒体变为 64–80px 胶片条；
- 返回、播放、关闭必须常驻；
- 复制路径、外部打开、次要元数据进入 overflow；
- Escape 返回默认布局，焦点返回触发元素。

## 4. 图标预算

### 常态保留

- 左导航：新建、搜索、当前工作区状态。
- 主聊天头：任务标题、运行/阻塞状态、overflow。
- 输入框：`+`、模型、发送/停止。
- 短剧面板：五个文字阶段、团队聚合入口、关闭。
- 媒体预览：返回/关闭、播放控制。

### 改为 hover / focus

- 用户消息：复制、编辑、回滚。
- AI 回复：复制。
- 媒体卡：引用、选择、删除。
- 资产/分镜结果：打开预览、引用详情。

所有 hover 动作必须同时支持 `:focus-visible` 或 `:focus-within`，不能成为鼠标专属功能。

### 收入 overflow

- 主聊天的 PR、轮次列表、上一轮/下一轮。
- AI 回复的分叉、导出图片。
- 媒体库的刷新、类型、状态、排序。
- 全屏媒体预览的复制路径。

## 5. 图片与结果行规则

### 聊天中的媒体生成

折叠态由“最多 6 张缩略图”改为一行：

```text
[代表图] 已生成 24 张 · 2 张失败                         查看
```

点击仍走现有 `openMediaPreview`；展开后继续使用完整网格和“设为参考”能力。

### 分镜

默认每镜 44–56px：

```text
[代表图] 12 号镜 · 中景 · 4.2 秒    3 个候选 / 4 个参考   已完成
```

选中后展开原 `MediaPreview + StoryboardReferenceChips`。视频主预览、镜头轨和后期成片不能折成纯文本行。

### 资产

资产仍需保留代表缩略图。默认只显示名称、类型和状态；摘要、媒体引用、修订、尝试、usage 放在详情层。

### 用户附件

默认最多显示 2 张 48px 缩略图，剩余显示 `+N`；点击继续打开现有 lightbox。

### 空状态

空阶段不再保留整列空白，而显示一条紧凑状态：

```text
尚无分镜 · 完成剧本资产后可生成                       前往资产
```

这只是导航提示，不自动触发生成。

## 6. 字体与密度

优先使用系统字体，避免新增字体下载和启动开销：

```css
font-family:
  Inter,
  "Segoe UI Variable Text",
  "PingFang SC",
  "Microsoft YaHei UI",
  sans-serif;
```

| 用途 | 字号 / 行高 | 字重 |
|---|---:|---:|
| 正文 | 13px / 20px | 400 |
| 紧凑结果行 | 12px / 18px | 400 |
| 次要信息 | 11px / 16px | 400 |
| 小标题 | 13px / 20px | 600 |
| 页面标题 | 14px / 22px | 600 |

正文最大行宽控制在约 720px。边框只用于分区和可交互边界；不使用重阴影、渐变、发光或大圆角卡片。

## 7. 不破坏功能的实现边界

只新增或调整 presentation/view 层。推荐显式状态：

```ts
interface MinimalWorkspaceViewState {
  shell: 'conversation' | 'media-focus';
  shortDramaPanel: 'closed' | 'open';
  teamPanel: 'closed' | 'open';
  expandedResultId: string | null;
  focusedMediaId: string | null;
}
```

这个状态只控制“怎么显示”，不推断媒体来源、生成状态或代理状态。现有模块接口是唯一事实来源。

不得删除或绕过：

- `getMediaToolViewModel` → `useWorkspaceMediaToolRefreshBridge` → `openMediaPreview` / `dispatchMediaReference`
- `workspaceMediaLibraryService.scanLibrary` → `createShortDramaMediaArtifactIndex` → `resolveWorkspaceMediaPreviewUrl` → `openMediaPreviewPanel`
- `onArtifactFocus`、`onStageSelect`、`onEpisodeSelect`、`MEditor.onChange`
- 团队 `onToggle`、`onSelectTab` 和代理状态投影
- `MEDIA_PREVIEW_EVENT`、本地/远程 URL fallback、焦点陷阱和 Escape 关闭

## 8. 推荐落地顺序

1. 媒体生成工具结果行：收益大、边界最清晰。
2. 分镜结果行：视觉降噪最大，保留选中后的完整组件。
3. 短剧按需面板和团队聚合入口：先建立 presentation 状态，不改代理运行时。
4. 媒体库 Filter 合并：13 个控件收为搜索、视图、Filter、overflow。
5. 主聊天头、消息动作和左导航降噪。
6. 媒体聚焦状态：最后接入，因为涉及焦点恢复和多类媒体验证。

每一步都应独立构建、类型检查、测试原处理函数映射，并在 1536×900、1366×768 和当前桌面尺寸下截图回归。

## 9. 验收条件

- 五个短剧阶段始终可见且可切换。
- 团队所有代理、状态和切换能力完整保留。
- 生成、停止、预览、引用、删除、恢复、永久删除、轮次导航均仍可达。
- 任何原操作最多增加一次展开动作。
- 键盘可到达所有被隐藏的操作，Escape 和焦点恢复正确。
- 视频主预览、镜头轨、后期成片、媒体库瀑布流不被错误折叠。
- 1536×900 下无横向或纵向页面级溢出。
- 设计改动不触碰服务、事件、文件扫描、代理调度和短剧运行时。
