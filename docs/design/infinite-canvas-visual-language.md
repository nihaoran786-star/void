# 无限画布视觉与交互语言（业主参考图定稿）

状态：现行设计契约。业主 2026-08-25 提供三张参考截图并拍板"照此重做"。
适用范围：`app/components/panels/content-canvas/infinite-canvas/` 的全部呈现层。
上位规范：[Canvas 插件平台 PRD](../features/canvas-plugin-platform-prd.md)（贡献点与边界）、
[无限画布契约](../features/infinite-canvas-and-media-tools-prd.md)（数据与命令）。
本文只管"长什么样、怎么操作"，不改任何数据契约。

---

## 0. 一句话

**画布是暗色的看片台，卡片就是媒体本身，所有控件平时都不在场。**
生成不在卡片上发起，而是画布底部一个浮动输入器。

这与当前实现（浅色、卡片像表单、提示词框常驻、按钮摊开）是形态级差异，
不是配色微调。重做时以本文为准，不要保留旧卡面结构。

---

## 1. 画布底板

- 极淡的点阵网格（点比现在更小更暗，几乎只在空处可见）。
- **画布跟随软件主题实时切换明暗**（2026-08-26 业主要求，推翻此前"恒为暗色"的
  取舍）。画布专属 token（`--canvas-surface-*` / `--canvas-text-*` /
  `--canvas-accent`）保留，但必须在暗色与浅色两套主题下各给一组取值，并随全局
  主题切换即时生效（不要求刷新面板）。
  - 暗色主题：即参考图那套近黑看片台。
  - 浅色主题：同一套形态的浅色版——极浅的底、更淡的点阵、深色文字；
    卡片、输入器、工具条、弹层一律跟着换，不允许出现"浅色界面里嵌一块黑板"。
  - 判定标准：明暗两套下文字对比度、卡片边界、连线与手柄都要清晰可辨。
- 不要给画布加边框、内阴影或渐变。

> **作废（2026-08-26）**：S1 曾把画布做成"两套主题解析为同一组暗色"的主题例外，
> 业主已推翻。画布专属 token 保留，但要按明暗两套主题各给一组取值并随全局主题
> 切换。[无限画布 PRD](../features/infinite-canvas-and-media-tools-prd.md)
> 的已知取舍里那条"主题例外"记录需同步删除或改写。

## 2. 卡片 = 媒体本身

参考图里的卡片没有任何"卡面装饰"：

- 图片/视频**铺满整张卡**，圆角约 12px，无内边距、无边框、无标题栏、
  **卡内不显示文件名**。保持媒体原始宽高比。
- 卡片阴影几乎不可见；只有选中态给一圈细描边（浅色 1px 或 accent）。
- **类型标签在卡片外部上方**：一个小图标 + 一行灰字（如 `Image Generation`、
  `Reference`、`Video Generation`、`Poem`、`Video-1786035456256`）。
  约 12–13px，无背景、无胶囊底，颜色是中性灰（比正文更暗）。
  已完成/已确认的产物可在标签后跟一个小蓝色对勾点。
- **空卡 / 生成中**：同尺寸的深色圆角矩形 + 极淡边框，正中一个静态占位图标
  （图片卡用图片图标，视频卡用播放图标）。生成中在此基础上叠一个克制的进度指示，
  不要大面积遮罩、不要文字长句。
- **文字卡**：深色圆角面板，只有文字本身，行高宽松、内边距充足，无标题、无边框。

## 3. 连线

- 细曲线（贝塞尔），中性灰，比现在更细更暗；不使用 accent 色除非选中。
- 线的**中点有一个小圆形手柄**（参考图里是圆圈内一个竖线/加号），用于在该连接上
  插入动作；卡片右缘外侧也有一个小圆形 `+`，用于从这张卡继续派生下一张。
  这两个手柄平时低透明度，悬停才变亮。
- 参考顺序角标（图一/图二）不要做成醒目胶囊，用与类型标签同级的灰字小标记。

### 3.1 断线（2026-08-26 业主要求）

连线必须可以删除，两条路径，行为一致：

- **点击连线选中** → 选中态用 accent 高亮（更粗一点点的 accent 描边），
  按 `Delete` / `Backspace` 删除。
- **中点手柄旁边一个小 `×`**（在插入手柄右侧约 20px，避免误点），
  与手柄同样平时不可见、悬停或选中才出现。

约束：

- 走既有的 `removeEdgesContent` 文档 mutate，**可撤销**，一次一条撤销记录。
- **不经过卡片删除确认弹窗**——断线不动任何卡片、不动任何媒体文件，没有要确认的。
- 两端卡片及其媒体一律不受影响。

## 4. 悬浮工具条（选中卡片时出现）

参考图第三张：一个**深色药丸形浮层，出现在卡片正上方**，纯图标、无文字。

- 图标之间用细竖线分组（编辑类 / 组织类 / 输出类）。
- 图标尺寸小而清晰，悬停变亮；新功能可在图标右上角点一个小蓝点。
- 我们的动作映射：裁剪、高清放大、局部重绘、擦除、抠图、再生成、更多(…)、
  风格、加入分组、另存、全屏。数量控制在 10 个左右，超出收进"更多"。
- 工具条不占布局空间，随选中态出现/消失。

## 5. 视频卡的内联播放条

参考图第三张：视频卡悬停或选中时，**在视频底部叠一条极简播放条**——
播放/暂停、已播时间、细进度条、总时长、右侧全屏图标；左上角一个静音切换。
非悬停时全部隐藏，卡片就是一帧画面。

## 5.1 全屏查看（2026-08-26 业主要求）

大图/视频浮在画布之上，图片与视频规则完全一致：

- **背景是模糊的**：`backdrop-filter: blur(18px)` + 半透明底色。
  底色取画布自身的背景 token，因此暗色主题下是暗底、浅色主题下是浅底，
  媒体在两套主题下都读得清；不允许写死黑色遮罩。
- **点击图片本身以外的任何位置就关闭**（即整片模糊区）；点媒体本身不关闭。
  顶部工具条与左右切换按钮属于"控件"，点它们同样不关闭。
- **Esc 关闭**，与第 7 节的弹层共用同一套关闭机制。
- 遮罩里除媒体外只保留既有的必要能力：文件名、序号、缩放、另存、左右切换。
  > **改写（2026-08-28，见 §7.4）**：此处曾写"不做关闭按钮"。全屏查看器现在
  > 接进统一的悬浮媒体台，它的药丸最左端与其余三个场景一样是 `×`；
  > 点模糊底板与 `Esc` 仍然关闭。这条只管**铺满型悬浮台**，
  > §7.2.1 末尾"轻量锚定浮层不做关闭按钮"对参数 / 模型 / 风格 / 图库 /
  > "更多"抽屉继续成立。

## 6. 生成输入器：依附于卡片，不是全局面板

> **2026-08-26 业主纠正（此前理解错误，以本节为准）**：参考图里那个输入器
> **不是常驻画布底部的全局输入框**。它属于**当前选中的那一张卡**，浮在该卡下方。
> 参考图第二张之所以有它，是因为用户从左边视频卡的 `+` 手柄拖到空白处，
> 生成了一张空白的"视频重拍"卡，输入器就是给这张新卡写提示词的地方。
> 第一版实现做成了常驻全局输入框，是错的，必须改掉。

规则：

- **没有选中任何卡片时，画布上不出现输入器。** 空画布就是干净的暗色板。
- **选中一张卡** → 在该卡**正下方**浮出输入器，内容是**这张卡上一轮的提示词**
  （可编辑）；参数摘要行、张数、发送按钮都作用于这张卡。
- **空白生成卡**（从已有卡右缘 `+` 手柄拖到空白处新建，或从左栏 `+` 新建）→
  选中时输入器为空，人工输入提示词后点发送 → 结果落进这张卡。
- **点击卡片 = 选中**（浮出输入器与工具条），**不得直接放大**。
  放大是显式动作：工具条的全屏图标或双击卡片。
- 从卡片右缘 `+` 手柄**拖到空白处**要新建一张空白卡并自动连线（源卡成为它的参考）；
  新卡的类型（图/视频）由手柄或随后的小菜单决定。

输入器自身的结构自上而下：
1. 顶行：参考图缩略图队列（每个是小方图）+ 一个 `+` 按钮添加参考；
   最左侧一个"引用/角色"图标按钮。
2. 主体：大号占位文案的多行输入区，例如
   "描述你想生成的内容，或输入 @ 调用素材库与快捷操作"。
   无边框，与面板同底色，字号偏大、颜色柔和。
3. 底栏（一行，全部是紧凑的灰字与小图标）：
   模型名 · 参数摘要（如 `Omni Reference · 16:9 · 720p · 5s`）· 声音开关 ·
   麦克风 · 张数（`1×`）· 余额/成本 · 圆形发送按钮（右侧，浅色实心箭头）。
   参数摘要点击展开我们已有的参数弹层，视觉按本文第 7 节重做。
- 面板深色、大圆角、轻微浮起；锚在卡片下方，随卡片移动与缩放；
  卡片被取消选中即消失。
- **卡面本身不再有任何输入控件**——输入只在这个依附式输入器里发生。

### 6.1 输入器与卡片的对位（2026-08-26 业主纠正）

第一版做成了"与卡片等宽、左对齐"，业主要求改为**双边对称、长一点点**：

- 宽度 = 卡片宽度 + 两侧各外扩 `GENERATOR_SIDE_OVERHANG`（当前 20px），
  并保留一个最小宽度（320px）以免小卡把输入行挤扁。
- **水平居中对齐卡片中线**——即使最小宽度生效，也仍然是居中的，
  绝不能退回左对齐。

### 6.2 参考图缩略图可删除（2026-08-26 业主要求）

- 每个参考缩略图右上角一个小 `×`，**悬停（或键盘聚焦）才出现**。
- 点击即断开这条参考连线：走第 3.1 节同一条 `removeEdgesContent` 通道，
  可撤销；参考卡片本身与两端媒体一律不动。

### 6.3 输入器的观感（2026-08-27 业主实机反馈）

业主原话："下方输入提示词的地方有点丑"。形态不变（仍是 §6 / §6.1 的依附式
输入器），只把观感做到对标图的水准：

- **底栏胶囊化**：不再是"默认 · 参数 · 1张"这种纯文字加圆点。
  模型名、参数摘要、张数各是一个**可点的小胶囊**（21px 高、全圆角、极淡底），
  参数胶囊显示**真实取值**（如 `21:9 · 1080p`），只有该卡还没设过参数时
  才退回"参数"字样。分隔符是**极淡的 1px 竖线**，不是圆点。
- **发送按钮**：28px 圆形实心，与底栏垂直居中；悬停微微上浮并向 accent 偏色，
  禁用态转为线色底、降低不透明度，两种状态一眼可辨。
- **提示词区**：字号 14.5px、行高 1.5、内边距收紧，占位文案更淡。
  聚焦提示只是**面板自身描边微微染上 accent**——不加粗边框、不加内发光。
- **参考图队列**：缩略图、风格按钮、`+` 一律 32px 见方、9px 圆角，
  同一行基线对齐；缩略图右上角的删除 `×`（§6.2）保持不变。
- 整体内边距收紧（9/11px），三行间距 6px；明暗两套主题都成立。

不改任何行为与数据流：这一节只管呈现。

### 6.4 输入器是全画布唯一的输入框（2026-08-27 业主实机反馈）

业主原话："所有的都是共用输入框的 设计风格一致"。铺满型编辑页**不得自建输入框**，
一律挂载 §6 这个同一个 `InfiniteCanvasGenerator` 组件，只切换"卡片形态 / 编辑页形态"：

| | 卡片形态（`surface="card"`） | 编辑页形态（`surface="editor"`） |
| --- | --- | --- |
| 位置 | 绝对定位，锚在选中卡下方，随卡移动 | 普通文档流，居中浮在媒体下方 |
| 参考图行 | 有（缩略图、风格、`+`） | **无**——编辑对象就是页面里那张图，另加参考不会被提交 |
| 占位文案 | "描述你想生成的内容…" | 由编辑页给（重绘/擦除是"要改成什么"） |
| 状态提示 | 无 | 顶部一行极短灰字（如"请先涂出你想修改的区域"） |
| 底栏 | 模型 · 参数 · 张数 · 圆形发送 | **完全相同** |
| 发送键 | 提交该卡的生成 | **就是编辑页的"确认"**——编辑页里不再另放确认按钮 |

- 编辑页打开时，**卡片形态的输入器让位**（同一张卡不出现两个输入框）。
- 提交语义不变：仍是"蒙版合成图作为编辑对象 + 输入器里的提示词"，
  走既有 `confirmMask` 那条链路。
- 编辑页里输入器打开的参数/模型弹层是编辑页的兄弟节点，
  因此编辑页 `z-index` 压在 `.infinite-canvas-popover` 之下，
  且这些弹层被声明为"算作编辑页内部"，点它们不会把编辑页关掉。
- 扩图这类**不需要提示词**的编辑页，按同一组件收起提示词区、只留底栏：
  `InfiniteCanvasGenerator` 的 `collapsePrompt` 开关（见 §7.2.2）。
  收起后底栏一字不改（模型 · 参数 · 张数 · 圆形发送），发送键仍是确认。

## 7. 弹层与选择器

- 统一深色、大圆角、无粗边框；标题一行小字，选项密排。
- 风格选择器与图库选择器：网格铺缩略图（暂无缩略图时用纯色块 + 名称），
  分类用极简的文字筛选行，不用彩色胶囊。
- 参数弹层：分组紧凑，取值以分段控件呈现；不可用取值置灰不可点（见 §7.3-D，
  此条已推翻早先"直接隐藏"的写法）。

### 7.1 一律是紧凑锚定浮层（2026-08-26 业主纠正）

第一版把三个弹层（参数 / 风格 / 图库）做成了近全屏的大页面，业主评价
"太粗糙太大…很丑"。现行规则：

- **锚定**在触发它的那个控件上（如输入器底栏的"参数"文字），
  优先向上弹出，上方放不下才翻到下方，并在视口内夹紧。
- **宽度 260–320px**（参数 280，风格与图库 320），高度上限约 380px，
  内容在浮层内部滚动，不允许把浮层撑大。
- 网格更密、卡片更小；风格选择器的"风格族"下拉与分类行**合并成一行**紧凑筛选，
  分类行横向滚动而不是换行把浮层撑开。
- 三个弹层共用同一个浮层组件与同一套主题 token，明暗两套都成立。

### 7.3 参数与模型浮层的形态（2026-08-26 业主再次给参考图）

业主实测反馈："我们的参数位置是会被隐藏的，位置不对会去下面"，并给出三张对标
截图。照抄以下形态：

**A. 拆成两个浮层，各自锚在底栏对应的那个词上**

- 底栏结构：`模型名` ｜ `参数摘要胶囊`（如 `首尾帧 · 21:9 · 1080p · 5s`）｜
  其余小控件 ｜ `张数` ｜ 发送。
- **点模型名** → 弹出**模型列表**浮层；**点参数摘要胶囊** → 弹出**参数**浮层。
  两者互斥，不塞在同一个面板里。

**B. 定位：一律向上弹出，且永不被裁切**

- 默认锚在触发控件的**正上方、左边缘对齐**触发控件。
- 上方空间不足才翻到下方；左右都要在面板可视区内**夹紧**（clamp），
  贴边时向内收，绝不允许溢出到画布外或被右缘裁掉——这正是业主看到的毛病。
- 浮层最大高度约 420px，超出在浮层内滚动。

**C. 模型列表的样子**

- 竖排列表，一行一个模型：模型图标 + 模型名（正常字号）；
  其下一行是**能力小胶囊**：分辨率（如 `1080P`）、时长范围（如 `4-15S`）、
  有声则加一个喇叭图标。胶囊是极小的圆角、描边、灰字。
- 当前选中项高亮；列表可滚动。能力值来自我们既有的模型能力表，不得臆造。

**D. 参数浮层的样子：分组 + 分段控件，不是自由散落的胶囊**

- 每组一行小灰字标题（`画质` / `比例` / `清晰度` / `生成时长` / `一次出几张`），
  组与组之间留白清楚。
- 取值用**等宽分段控件**（segmented）或**等宽小格**，一行排开、对齐整齐；
  不要现在这种长短不一、换行乱撞的胶囊流。
- **比例的每个格子里画一个该比例的小矩形示意图**（如 21:9 是扁长条、9:16 是竖条），
  下面是文字标签；`自适应 / auto` 排在第一个。这是参考图最直观的一点。
- **不可用的取值照常显示但置灰不可点**（参考图里 4K、480p 就是灰的），
  **推翻此前"直接隐藏"的写法**——隐藏会让人以为功能不存在。
  置灰项要能说明原因（title 或组末一行小字，如"该模型一次只能出一张"）。

**E. 视觉**

- 半透明深色 + 轻微模糊，大圆角（约 16px），无标题栏、无关闭按钮；
  明暗两套主题都要成立（浅色主题下是半透明浅色 + 深色文字）。

### 7.2 关闭方式统一（2026-08-26 业主要求）

- **轻量浮层一律不做"关闭"按钮。**
- 点击弹层外任意处关闭；`Esc` 关闭。
- 这套行为只写一次：共用 hook `useInfiniteCanvasDismiss`
  （捕获阶段的 `mousedown` + `Esc`），三个弹层与第 5.1 节的全屏查看器全部复用它，
  不允许每处各写一遍。
  - hook 支持声明"额外算作内部的区域"（如查看器的工具条与左右切换）
    与"忽略的触发控件"（打开它的那个按钮，否则按下就关、松开又被重新打开）。

### 7.2.1 铺满型编辑页 = 悬浮媒体 + 一条浮动药丸（2026-08-27 业主实机反馈，两次）

业主原话（第一次）："现状这些页面都没有返回按键"；
（第二次，附两张对标截图）："裁剪页面等 这些所有功能页面 全做成悬浮效果。
删除上边栏。保持当前极简高级风格"。**以第二次为准**，此前"裁剪在顶部操作条、
涂抹在底部提示行"的写法作废。

适用对象：占满整块画布并接管操作的编辑页。目前三个——涂抹重绘/擦除
（`InfiniteCanvasMaskEditor`）、裁剪（`InfiniteCanvasCropEditor`）
与扩图（`InfiniteCanvasExpandEditor`，见 §7.2.2）。

形态写死如下：

- **没有顶栏，也没有底部条。** 页面上只有三样东西，垂直居中成一叠：
  **药丸 → 媒体 → 输入器**（裁剪没有输入器）。
- **背景与 §5.1 全屏查看共用一套**：`backdrop-filter: blur(18px)` +
  取自画布背景 token 的半透明底（暗色主题暗底、浅色主题浅底），
  不允许写死黑色遮罩。
- **媒体悬浮居中**，尺寸按视口封顶（裁剪 64vh、涂抹 52vh，留出输入器的位置），
  大圆角 + 一层柔和投影。媒体本身就是"内部"，点它不关闭。
- **一条浮动药丸，浮在媒体正上方**，与 §4 卡片工具条同一套语言：
  半透明 overlay 底、全圆角、细竖线分组、纯图标为主、悬停提亮、
  次要控件一律透明底灰图标。
  - **最左端是出口 `×`**，与后面的工具用一条细竖线隔开。不是文字按钮。
  - 涂抹页药丸：`×` ｜ 笔刷 / 矩形 / 橡皮 ｜ 粗细滑杆 ｜ 撤销 / 重做 / 清空。
  - 裁剪页药丸：`×` ｜ 当前尺寸（灰色等宽数字）｜ 确认（accent 实心小按钮）。
    裁剪没有提示词、也就没有输入器可发送，**是唯一还把主行动放在药丸里的页面**；
    涂抹页的主行动是输入器上的圆形发送键（见 §6.4）。
- **出口行为一条路**：`×`、`Esc`、点模糊遮罩区，三者都走同一个 `requestClose`。
  药丸与输入器被声明为"算作内部"，点它们不关闭。
  > **作废（2026-08-28，见 §7.4.2）**：此处曾要求"有未保存笔迹 / 已调整框选时
  > 一律先弹放弃确认"。业主已推翻——关闭一律不问。
- **解码失败时药丸仍然在**：`data-ready` 永远不会变 true，
  若把药丸也藏进"测量前不显示"的门里，用户就会得到一个没有任何出口的黑屏。
- **极简**：不要标题、不要说明段落、不要边框套边框。
  必要提示只允许一行极短灰字，放在药丸下方或输入器顶部。
- **轻量锚定浮层与全屏查看器仍然不做关闭按钮**：参数 / 模型 / 风格 / 图库 /
  "更多"抽屉、以及 5.1 的全屏查看器，一律只靠点外面与 `Esc`。业主明确不喜欢
  在这些地方出现 `×`。判定口径：**它是否占满整块画布并接管操作**。

### 7.2.2 扩图编辑页 = 悬浮媒体 + 可拖外框（2026-08-27 业主对标图）

扩图（outpainting）此前只是"更多"抽屉里一条纯文字指令
（"向【方向】扩展画布并填充【场景描述】"），扩多少全靠模型猜。
业主给的对标截图把它做成第三个悬浮编辑页：**图浮在中间，外面套一个可拖的外框，
往外拖多少就扩多少**。本节写死这个形态，其余一切沿用 §7.2.1 与 §6.4。

- **三段叠放不变**：药丸 → 媒体 → 输入器，背景与 §5.1 共用同一套模糊底板。
- **媒体不再铺满舞台**：舞台就是"目标画布"，原图按百分比定位在舞台内部，
  原图与舞台边缘之间的空档，就是要生成的新画面。
  舞台自身按**比例**（`aspect-ratio` + 视口封顶的 `min()`）取尺寸，
  **不读任何布局测量**——坐标换算与"测量前不显示"两条教训在这里同样成立。
- **外框只有八个白色短角标**：四角是短折角、四边中点是短横/竖条，
  不是实线满框（对标图如此，也免得一层框套一层框）。
  白色在这里与蒙版的红一样是**功能色**，要在任意照片上都看得见，不随明暗主题走；
  它脚下的底板才跟主题。
- **只能向外扩，且有上限**：
  - 向内拖一律被 `clampExpandInsets` 夹回 0。扩图必须保证原图分毫不动，
    一个比原图小的框会悄悄变成裁剪，那是另一个功能。
  - 每边最多扩到该轴的一倍（`CANVAS_EXPAND_MAX_RATIO = 1`，即每轴最大 3 倍）。
    上限不是装饰：合成图要过 32MB 写入上限，无上限的拖拽会把两秒钟的手势
    变成一句用户对不上号的 `invalid_input`。
- **药丸内容**：`×` ｜ 当前宽高比（灰色等宽数字，如 `3 : 1`）｜ 一行极短灰字
  "拖拽外框进行扩图"。
  - 这里**没有比例预设**——比例就是用户拖出来的那个，所以药丸只**报告**它，
    不摆一个点了不起作用的控件（§7 "不造假控件"）。
  - 主行动不在药丸里（裁剪仍是唯一的例外），在输入器的圆形发送键上。
- **输入器：收起提示词区**。对标图里扩图没有大提示词输入框，只有底栏那一条。
  仍然是 §6 同一个 `InfiniteCanvasGenerator`，`surface="editor"` 且
  `collapsePrompt`；未拖动外框时发送键置灰，顶部一行灰字说明为什么。
- **出口行为**与 §7.2.1 完全一致：`×`、`Esc`、点模糊遮罩三者同一个 `requestClose`。
  > **作废（2026-08-28，见 §7.4.2）**：此处曾要求"外框拖出去过就先弹放弃确认"。

提交语义（不新造后端，与重绘同一条链路）：

1. 前端把"原图 + 外扩后的透明留白"合成为一张目标尺寸 PNG
   （`expandBitmap`，原图按拖出的偏移一次 `drawImage`，其余保持透明）。
2. 经既有 `write_canvas_image_bytes` 写进 scratch
   （`canvasScratchRelativePath(operationId, 'expand')`，落在四个媒体扫描根之外）。
3. 该文件作为 `editTargetMediaRef`，经既有 `DirectImageGenerationGateway` 提交，
   `kind: 'expand'`、`resultMode: 'derived'`、不带任何其他参考图。
4. 指令仍用 `IMAGE_TOOL_DEFINITIONS` 里 expand 的既有模板，
   两个【】占位由外框自动填（拖了哪几边 / "自然延续现有画面"），
   前面缀上一句解释透明留白的 directive——与蒙版那条 directive 同一套写法。
5. 派生新卡、原卡 `mediaRef` 分毫不动。写盘失败绝不提交（钱的规矩）。

"更多"抽屉里的扩图入口保留，只是它打开的东西变了。


## 7.4 统一的悬浮媒体台（2026-08-28 业主定稿，收编 5.1 / 7.2.1 / 7.2.2）

业主原话："所有功能点击 图片变大的时候都是悬浮的 统一风格"、"放大图片也是 跟涂抹
用的一样 悬浮效果"、"能复用的就复用设计 一个设计好看可以统一复用"。

**只有一套壳。** 凡是"把图放大到画布之上"的场合——全屏查看、涂抹重绘 / 擦除、
裁剪、扩图——共用同一个悬浮媒体台组件，不允许各写各的：

- 模糊底板：`backdrop-filter` + 取自画布 token 的半透明底（明暗两套各自成立）。
- 媒体悬浮居中，尺寸上限一致。
- **上方一条浮动药丸**：最左永远是 `×`，其后用细竖线分组放该场景的工具。
- **下方是共用的生成输入器**（`InfiniteCanvasGenerator` 的编辑页模式）；
  该场景不需要写提示词时用 `collapsePrompt` 收起输入区，只留底栏。
- 5.1（全屏查看）、7.2.1（涂抹）、7.2.2（扩图）以及裁剪，全部是这个壳的不同装配，
  差异只在药丸内容与是否收起提示词区。**新增任何"放大看图/编辑图"的功能一律复用它。**

**落地形态（2026-08-28 实现）**：`InfiniteCanvasMediaStage`。壳自己拥有模糊底板、
药丸（含永远在最左的 `×`）、居中媒体区、输入器插槽与那一套关闭契约；
场景只给三样东西——药丸里放什么、媒体是什么、有没有输入器。
"测量前不显示"的门只罩住**媒体区**：解码失败时 `data-ready` 永远不会变 true，
把药丸一起藏起来就等于给用户一块没有出口的黑屏。

### 7.4.1 裁剪与扩图是同一个框编辑器的两个方向

业主原话："扩图和截图技术一致 只不过是圈主图片外面"。

- 两者合并为**一个框编辑器组件**，只有一个方向参数：
  - **向内** = 裁剪：框在图内，取框内。
  - **向外** = 扩图：框在图外，图与框之间的留白交给模型补。
- 手柄、拖拽、夹紧、比例显示、键盘操作全部同一套代码，不允许两份实现。
- 两者的提交都走既有链路：裁剪本地成图落 `media/input/canvas-crops/`；
  扩图合成透明留白落 scratch 后经生成通道提交。方向不同，几何一致。

**落地形态（2026-08-28 实现）**：`InfiniteCanvasFrameEditor` + `direction` 参数，
几何全部在 `infiniteCanvasFrameGeometry.ts`。状态是**四条边到原图各边的偏移，
向外为正**：向外时它就是既有的 `CanvasExpandInsets`，向内时全为负、可无损换回裁剪
矩形。这样拖拽公式对两个方向**完全同一行**（西手柄恒为 `left - dx`，东手柄恒为
`right + dx`），只有夹紧函数知道自己在哪个方向：

- **向内**：手柄拖过对边先镜像（每个裁剪工具都这么做），再由 `clampCropRect`
  收进原图并保住 `CANVAS_CROP_MIN_SIZE`。框体可整体平移。
- **向外**：`clampExpandInsets` 拒绝一切负值（往内拖会悄悄变成裁剪，而原图必须
  分毫不动），并按 `CANVAS_EXPAND_MAX_RATIO` 每轴封顶（合成图要过 32MB 写入上限）。
  框体**不可平移**——不含原图的外框不是任何东西的扩展。

渲染也是同一套：一个**舞台**（两者中较大的那个：裁剪时是原图，扩图时是目标画布）、
原图按百分比落在舞台上、框按百分比盖在舞台上，八个手柄骑在框上。舞台按
`aspect-ratio` 取尺寸，不读任何布局测量。手柄是 `button`，方向键可微调（Shift 十倍），
走的是与指针完全相同的那一条夹紧路径。

**裁剪的确认按钮为什么还在药丸里**：主行动的位置由"这个场景有没有输入器"决定，
不由功能名决定。扩图要写提示词通道（哪怕收起提示词区），所以它有输入器、
主行动就是那颗圆形发送键；裁剪是纯本地成图、不发送、不花钱、没有可写的句子，
因此不挂输入器，也就没有发送键可用——它是唯一把主行动留在药丸内的场景。
这与 §7.2.1 的口径一致，只是理由从"裁剪特殊"改写成"有没有输入器"，两个方向
用的是同一条判据。

### 7.4.2 关闭不问（2026-08-28 业主要求）

业主原话："点击关闭不要有提示"。

- `×` / `Esc` / 点模糊底板一律**直接关闭**，不弹放弃确认。
- 编辑页里的笔迹与框选是草稿，关掉即弃；原图与文档从未被改动，没有可丢失的成果。
- 此条**推翻** 7.2.1 里"有未保存笔迹时先弹放弃确认"的写法。

## 7.5 选中风格后要显示缩略图（2026-08-28 业主要求）

- 输入器上的风格入口，在选中某个风格后要**显示该风格的缩略图**（小方图 + 名称），
  不能只剩一个名字或一个通用图标。
- 缩略图取 §W5 搬入的 `thumbnailRef`；该风格没有图时用既有的确定性色块（同一形状、
  同一圆角），保证有图与无图两种形态都是完成态。

## 7.6 一张卡承载多张图（2026-08-28 业主要求）

业主原话："支持在同一张卡牌上生成多张图，然后右上角会有缩略记录数量，点击展开折叠
展示所有图片。以四宫格的方式，多出来的就可以翻页 要风格统一"。

**这条改变落图规则，优先于此前的批量分身做法。**

- 对同一张卡的**生成与再生成**（含一次出多张）**累积到这张卡上**，成为它的多张图，
  而不是各自长出兄弟卡。卡面显示当前选中的那一张。
- **右上角一个小计数角标**（如 `4`），风格与 §2 的类型标签同级、克制不抢戏。
- 点角标**展开/折叠**该卡的图库：**四宫格**铺开，超出四张**翻页**；
  点某张即把它设为卡面当前图。视觉沿用 §7.1 的紧凑浮层与 §7.4 的同一套语言。
- **累积是追加，不是覆盖**：已存在的每一张都不可变更或替换，
  §"mediaRef 不可变"的不变量继续成立，只是卡从"一张图"变成"一列图 + 一个当前项"。
- 五件套（局部重绘 / 擦除 / 裁剪 / 扩图 / 高清放大）**仍然派生新卡**——
  它们是把图变成另一张图的加工，血缘关系要看得见；累积只适用于同一意图的反复生成。

## 10. 会花钱的动作要先问一句（2026-08-27 业主批准）

**倒推提示词（反推提示词）**会调用一次视觉模型并按该模型计费，因此点它
**不再直接发起调用**，而是先弹一个确认：

- 复用 §7.1 的**紧凑锚定浮层**（宽 280，锚在触发它的那一项上），
  不做成大弹窗、不做成两步向导——就一行说明加两个小胶囊按钮。
- 文案短：说明"这会调用一次视觉模型，按你配置的模型计费"，
  一个确认、一个"先不要"。i18n 三语。
- **确认之前一次调用都不发。** 点外面、`Esc`、"先不要"三条路都等于不发起，
  与 §7.2 的关闭语义一致。
- 确认后才走既有的调用路径，**既有的"正在看图并写出提示词…"进行中提示保留**，
  后续的"替换 / 接在下面"选择也完全不变。

裁剪、涂抹这类纯本机操作**不加这层确认**——它们不花钱，加了只是碍事。

## 实施约束（不可违反）

- 纯呈现层重做：不动数据契约、命令、绑定、桥接、撤销栈等任何逻辑。
- 媒体加载继续走 `resolveInfiniteCanvasMediaPreviewUrl`（`forceDataUrl`）——
  本应用未启用 assetProtocol，改回流式 URL 会让整片卡变空白。
  - **这条也适用于图库选择器的缩略图**（2026-08-26 业主实机反馈的真 bug）：
    `WorkspaceMediaLibrary` 填的 `item.thumbnailUrl` 是 `convertFileSrc` 产物
    （`http://asset.localhost/...`），webview 一律拒载，整屏都是破图。
    画布内任何地方都不得直接用 `thumbnailUrl` / `previewUrl`。
  - 图库条目的显示名不得只用 `fileName`：各批次首图都叫 `image-001.png`。
    用"批次 / 文件名"（`generatedIdentity.batchId`，无则用所在目录名）。
- 源码零新增 CJK；所有文案走 i18n 三语。
- 新增代码留在 surface 懒加载 chunk，入口体积预算不得变化。
- 现有行为测试必须继续通过；结构变化时按行为语义更新测试，不做样式断言。
